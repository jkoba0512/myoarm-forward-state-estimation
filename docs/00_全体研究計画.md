# myoArm 新規研究群 全体研究計画

## 研究群の中心テーマ

旧 `myoarm-lambda-ep` では、Feldman λ-EP / referent control を中心に myoArm reaching を説明しようとした。しかし、重力下の多自由度筋骨格 plant では、単純な kinematic λ recipe だけでは静的保持・重力補償・精密 reaching が不十分であることが分かった。

新しい研究群では、中心テーマを次のように置く。

> 重力下のヒト様筋骨格 reaching では、筋活動や軌道を直接指定するだけでは不十分であり、forward prediction、状態推定、不確実性統合、population dynamics、神経解剖に着想を得た制御構造がどの程度必要かを myoArm で検証する。

## 全体アーキテクチャの見取り図

```text
task goal / target / context
        ↓
cortical population dynamics or controller
        ↓
neural_command / excitation
        ↓
MyoSuite myoArm plant
        ↓
true state, delayed/noisy sensory feedback
        ↓
forward model prediction
        ↓
Kalman-like / Bayesian state estimator
        ↓
estimated state
        ↺ controller
```

重要な区別:

- `api_action`: Gym / MyoSuite に渡す API 入力。
- `neural_command`: controller が出す抽象的な運動指令。
- `excitation`: 筋 actuator への入力として解釈する量。
- `activation`: 筋モデル内部の活性化状態。
- `state_estimate`: controller が利用可能な推定状態。
- `true_state`: シミュレータ内部の真の状態。oracle baseline 以外では controller に渡さない。

## プロジェクト候補

### Project 0: 共通 myoArm 基盤

全プロジェクトの土台。

目的:

- target set、episode logging、action adapter、noise/delay wrapper、metrics を統一する。
- `horizon`, `dt`, `max_steps`, `api_action`, `excitation`, `activation` の混同を防ぐ。

成果物:

- `MyoArmEpisodeLogger`
- `ActionAdapter`
- `SignalDependentMotorNoise`
- `DelayedObservationWrapper`
- `NoisyObservationWrapper`
- `MyoArmMetrics`
- reproducible target set

### Project 1: Forward model + Kalman-like state estimation

最初に着手する本体プロジェクト。

中心問い:

> myoArm reaching において、forward model と Kalman-like state estimator は、遅延・ノイズ・SDN 下の reaching を改善するか。

理由:

- 後続の Bayesian integration、cortico-cerebellar loop、cortical population dynamics の基盤になる。
- シミュレータでは true state が取れるため、state estimation error を直接評価できる。
- 成功しても失敗しても、後続研究の設計に必要な情報が得られる。

詳細計画:

- [[01_Project1_ForwardStateEstimation研究計画]]

### Project 2: Bayesian reliability-weighted integration

Project 1 の estimator を拡張し、視覚、固有受容、prediction、prior の重みづけを扱う。

中心問い:

> 視覚・固有受容・forward prediction・task prior を不確実性に応じて重みづけ統合すると、state estimate、endpoint bias、variability はヒト行動実験と同じ方向に変化するか。

前提:

- Project 1 の forward model と delay/noise wrappers。

主な実験:

- visual noise / proprioceptive noise の操作
- sensory conflict
- target prior bias
- delayed visual feedback
- adaptive prior

### Project 3: 皮質-橋核-小脳-視床-皮質ループ

forward model を単一 black-box とせず、神経解剖に着想を得たループ構造に分解する。

中心問い:

> 皮質-橋核-小脳-視床-皮質ループに着想を得た分解構造は、単一 forward model よりも prediction、state estimation、robust reaching に有利か。

候補モジュール:

- `CorticalController`
- `PontineEncoder`
- `CerebellarForwardModel`
- `ThalamicRelay`
- `CorticalEstimator`

### Project 4: 解剖制約付き cortical population dynamics

M1 を完全再現するのではなく、M1 の解剖・生理制約を持つ population dynamics generator を作る。

中心問い:

> E/I 分離、Dale's law、層構造、L5 PT readout を持つ cortical dynamics module は、制約のない RNN / MLP policy よりも myoArm reaching で有効か。

候補モジュール:

- `LayeredEIRateNetwork`
- `CorticalInputAdapter`
- `CorticospinalReadout`
- `PopulationDynamicsMetrics`

## 推奨順序

```text
0. 共通 myoArm 基盤
1. Forward model baseline
2. Kalman-like state estimation
3. Bayesian integration
4. 皮質-橋核-小脳-視床-皮質ループ
5. 解剖制約付き cortical population dynamics
```

この順序にする理由:

- Project 1 以降は全て共通 logging / delay / noise / metrics に依存する。
- Kalman-like update には forward prediction が必要。
- Bayesian integration には複数の不確実な情報源が必要。
- ループ構造や cortical dynamics は自由度が高いため、先に baseline を固めないと原因切り分けが難しい。

## 共通評価軸

制御性能:

- static holding error
- static target equilibrium error
- minimum / final tip error
- success rate
- peak speed
- jerk RMS / normalized jerk
- straightness
- effort / activation norm
- co-contraction
- perturbation recovery
- altered gravity adaptation

推定性能:

- one-step prediction error
- multi-step rollout error
- state estimation error
- delayed feedback recovery
- noise robustness
- uncertainty calibration

表現解析:

- latent dimensionality
- jPCA 的 rotational dynamics
- target-condition separation
- synergy structure
- E/I balance stability

## 最初の実装チェックリスト

Project 1 に入る前に最低限必要なもの:

- `horizon=600` など episode 長を明示的に設定する。
- `dt=0.02 s` と MuJoCo internal timestep `0.002 s` を区別する。
- target set を固定し、train / validation / test に分ける。
- `api_action`, `excitation`, `activation`, `neural_command` の変換を明文化する。
- SDN は MyoSuite 標準にはないため、研究側で明示的に実装する。
- true state controller を oracle baseline として実装する。
- controller が見る observation と、評価に使う true state を分ける。
